# GEO Desk · AI 搜索可见度工作台

一个装在 [DeepSeek Harness](https://github.com/deepseek-ai) 侧栏的 GEO（Generative Engine Optimization）操作台：
把「问题库 → 采样 → 指标 → 洞察 → 行动 → 报告」跑成一条可复算的链路。

> **这是一个脱敏演示仓库。** 客户是虚构化的「广州某潮汕菜品牌」：品牌名、门店、年份、门店数、榜单名称
> 都已替换，数据里的同行用「同行 A–T」代替。指标口径、解析逻辑、报告结构都是真实项目在用的那一套。

## 它解决什么问题

品牌在 AI 回答里「被提到」只是结果。真正要回答的是三件事：

1. **现在什么水平** —— 非品牌词提及率、推荐位次、声量份额、信息准确率，全部带区间。
2. **为什么** —— AI 信哪些源（媒体、榜单、百科、点评、视频）、什么类型的问题偏好什么源、它抄走的是哪一句。
3. **怎么办** —— 每条缺口翻译成一张动作卡：为什么做、打哪几个问题、写什么、发到哪、怎么验收、多少工时。

## 三层结构

| 层 | 文件 | 做什么 |
| --- | --- | --- |
| 监测 | `src/metrics.js` | 提及率、前三率、SOV、引用率、准确率；Wilson 区间；品牌词/非品牌词分开算 |
| 洞察 | `src/insights.js` | 信源类型结构、按意图的引用偏好、字段出现率、被引句特征、没占到的源 |
| 行动 | `src/actions.js` | 事实纠偏、按意图补内容、信源占位、写作规范；每条带 brief 与验收 |

## 指标口径（容易做错的地方）

- **品牌词和非品牌词必须分开算**。问「某品牌怎么样」时答案里出现品牌是必然的，混在一起会把提及率抬到 40%+；
  真正的「AI 会不会想到你」只看非品牌词。
- **回答不稳定**。同一批问题、同一个引擎，隔一小时重跑，提及率会差 3 个百分点（都在区间内）。
  所以对外只报区间和趋势，不报单点。
- **准确率只查「说错」，不查「没说」**。没说只是信息不全，说错才是风险。
- **原文优先**。每条答案存原文与引用源，解析结果是派生的，解析器升级后历史数据可重算。

## 跑起来

需要 Node 20+、一个 [Tavily](https://tavily.com) key（用于检索），以及 Harness 里已配置的模型。

```bash
# 1. 把 Tavily key 放进环境（或 $DSH_HOME/.env）
export TAVILY_API_KEY=tvly-...

# 2. 安装到 Harness（在插件目录执行）
#    Plugins → Add plugin → 选这个目录；或用 plugin_manager install_bundle

# 3. 侧栏打开「GEO 工作台」→「跑一轮」
```

一轮是 60 个问题 × 2 次采样 = 120 次检索 + 生成，约 10 分钟。

## 离线生成报告

不依赖浏览器，直接用命令行复算指标、渲染报告：

```bash
node scripts/render.cjs        # 读 demo/answers.jsonl，出 reports/demo-baseline.html
node scripts/panel-smoke.cjs   # 用假 React 把四个屏渲染一遍，抓运行时错误
```

## 数据

- `demo/answers.jsonl` —— 脱敏后的示例采样（含原文、引用源、解析结果）
- `$DSH_HOME/geo-desk/clients/<slug>/` —— 运行时数据（不进仓库）

## 引擎

当前实现是 `Proxy-Web`：Tavily 检索前 8 条 → 模型按消费者视角组织答案 → 解析。
它模拟「联网搜索型答案引擎」，用来验证链路，不等于任何一个具体产品的输出。
要接真实引擎（豆包等），只换 `src/engine.js` 里的 `probe()`，指标、洞察、报告都不用改。

## 已知限制

- 单客户、单引擎、单轮，多轮对比还没做。
- 域名分类规则还有约 18% 落到「其他」，需要继续补。
- 面板只在结构上验证过（渲染无异常），没有做视觉回归。
- 采样用浏览器登录态时，吞吐约 60–90 次/小时，风控会中断，需要人工介入。
